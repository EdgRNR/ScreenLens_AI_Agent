# ScreenLens — AI 自主开发任务书

## 1. 项目定位

开发一款 Windows 桌面端轻量工具。

核心目标：

> 用户通过全局快捷键呼出工具，在屏幕上自由圈选任意不规则区域，截取该区域内容，并自动识别其中的文字；用户可以立即复制文字或进行翻译。

第一阶段重点不是做“大而全”的 AI 助手，而是把：

**自由截图 → OCR → 翻译**

这条核心链路做到稳定、快速、自然。

- 项目代号：`ScreenLens`
- 目标平台：Windows 10 / Windows 11
- 产品形态：常驻后台的轻量桌面工具
- 开发原则：由 Agent 自主选择技术栈、实现方式和工程结构，不要求人工逐步指导代码实现

---

## 2. 产品愿景

ScreenLens 是一个“屏幕内容理解入口”。

用户看到屏幕上的任何内容，不需要复制、切换窗口或手动截图，只需要：

1. 呼出工具
2. 圈选内容
3. 自动识别
4. 复制 / 翻译

未来可以在此基础上扩展：

- AI 解释
- AI 总结
- 代码识别与解释
- 数学公式识别
- 图片内容理解
- 多语言翻译
- 本地小模型
- 云端大模型
- 插件系统

这些属于未来扩展，本阶段不要为了它们过度设计。

# 4. 核心功能

## 4.1 全局快捷键

程序启动后常驻后台。

用户可以通过全局快捷键启动截图。

要求：

- 即使当前正在使用其他应用，也可以呼出
- 快捷键不要与常见系统快捷键冲突
- 快捷键最好允许未来配置
- 截图完成后自动退出截图模式

如果默认快捷键无法合理实现，由 Agent 自行选择一个合理方案，并在 README 中说明。

---

## 4.2 截图模式

进入截图模式后：

- 当前屏幕出现轻微暗色遮罩
- 鼠标操作区域保持清晰
- 鼠标指针应该清楚可见
- 显示当前选区
- 显示操作提示，但不要过度干扰

截图工具应该尽量做到：

> 用户第一次使用就知道怎么操作。

---

# 5. 自由形状截图

这是本项目最重要的特色之一。

不要只实现普通矩形截图。

至少支持：

### 模式 A：矩形截图

鼠标按下并拖动，形成矩形区域。

### 模式 B：自由形状截图

用户可以按住鼠标并自由绘制闭合区域，例如：

- 圆形
- 椭圆
- 任意曲线
- 不规则多边形
- 手绘圈选

例如用户看到一句话，只需要：

“圈一下这句话”

而不是必须精确拖出一个矩形。

---

## 5.1 自由形状区域处理

需要注意：

OCR 引擎通常处理的是矩形图片，因此自由形状区域可以：

1. 根据用户绘制路径计算最小包围矩形
2. 截取包围矩形
3. 将路径之外的区域设置为透明或背景遮罩
4. 再送入 OCR

实际实现方式由 Agent 自行决定。

重点是：

**用户感知到的是“自由圈选”，而不是普通矩形截图。**

---

# 6. OCR

OCR 是核心功能。

第一阶段要求：

- 支持中文
- 支持英文
- 支持中英文混合
- 尽量支持日文
- 自动识别文字方向和基本布局
- 对常见网页、聊天窗口、软件界面文字具有较好的识别效果

## OCR 架构要求

优先考虑：

> 本地 OCR

原因：

- 速度快
- 隐私更好
- 不依赖网络
- 成本低
- 可以离线工作

Agent 可以自行选择合适的 OCR 技术。

不要为了追求所谓“最先进模型”而让软件变得非常臃肿。

如果本地 OCR 无法满足某些场景，可以预留未来接入云端 OCR / 大模型视觉识别的扩展接口。

---

# 7. OCR 结果界面

识别完成后，需要给用户一个非常轻量的结果界面。

至少包含：

- OCR 文字
- 一键复制
- 翻译按钮
- 关闭
- 重新截图

界面不要做成复杂的传统软件窗口。

建议采用：

> 小型悬浮面板 / Popup / 浮窗

让用户感觉：

“截图之后结果就在旁边出现了。”

---

# 8. 翻译功能

用户点击“翻译”后，将 OCR 结果转换为目标语言。

第一阶段至少考虑：

- 中文
- 英文
- 日文

目标语言可以设计成：

`原文 → 目标语言`

例如：

英文：

`Hello, how are you?`

点击翻译：

`你好，你最近怎么样？`

---

# 9. 翻译架构

翻译功能需要考虑两种模式：

## 模式 A：在线大模型 / 翻译 API

用于获得更好的上下文理解和翻译质量。

例如未来可以接入：

- OpenAI
- Claude
- Gemini
- DeepSeek
- 其他兼容 API

第一阶段不要求绑定某一家服务。

应该尽可能设计成可替换 Provider。

例如概念上：

`TranslationProvider`

↓

`OpenAIProvider`

`GeminiProvider`

`LocalProvider`

等。

具体实现方式由 Agent 决定。

---

## 模式 B：本地模型

未来可以支持：

- 本地翻译模型
- 本地 OCR 模型
- 本地视觉模型

第一阶段可以预留接口，但不要因为预留功能而增加不必要复杂度。

---

# 10. 隐私

这是一个桌面截图工具，因此隐私非常重要。

原则：

### 默认情况下

截图和 OCR 尽可能在本地完成。

如果调用在线 AI / 翻译服务：

- 明确告诉用户内容会发送到网络服务
- 不应默认偷偷上传截图
- API Key 不应硬编码
- 用户应该可以关闭在线功能

---

# 11. UI / UX 原则

整体风格：

**极简、现代、快速。**

不要做成传统工具软件。

设计关键词：

- Minimal
- Fast
- Clean
- Lightweight
- Native
- Unobtrusive

用户应该感觉：

> “它一直在那里，但平时几乎感觉不到它。”

截图时：

> “一按快捷键就出来。”

OCR 后：

> “结果马上就在眼前。”

---

# 12. 性能目标

这是一个常驻后台工具，因此需要关注资源占用。

目标：

- 启动速度快
- 常驻后台占用尽可能低
- 截图操作流畅
- OCR 不应明显卡顿 UI
- 翻译请求不能阻塞主界面
- 失败时必须有明确提示

不要为了追求复杂架构而牺牲启动速度和稳定性。

---

# 13. 错误处理

必须考虑：

### OCR 失败

显示：

> 未识别到文字

同时允许用户重新截图。

### 翻译失败

显示：

> 翻译失败，请检查网络或服务配置。

不要直接崩溃。

### API 未配置

应该告诉用户：

> 当前未配置在线翻译服务。

而不是程序报错。

### 快捷键冲突

应该给出明确提示，并允许更换快捷键。
