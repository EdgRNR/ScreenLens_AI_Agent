# ScreenLens WinUI 前端修复与界面优化阶段计划书

> 阶段：第五阶段——WinUI 前端质量修复与视觉打磨  
> 状态：待 AI 执行  
> 范围：只完善 `winui/ScreenLens.WinUI/` 内的前端原型，不连接任何业务后端。

## 1. 阶段目标

基于第四阶段已生成的 WinUI 3 前端，先修复影响控件呈现和导航的结构问题，再改善演示交互的真实性、页面布局和视觉一致性。完成后，用户可以清楚地浏览设置页、操作本地演示控件、体验截图选区与结果面板的前端样机。

视觉方向继续参考用户提供的 Lyricify 设置页：深色侧栏、稳定的页面层级、分组设置卡片、图标 / 标题 / 描述 / 控件对齐。保留 ScreenLens 自身品牌和颜色，不复制 Lyricify 的代码、品牌、图标或文案。

## 2. 执行前检查

开始修改前，先检查当前 WinUI 项目和工作区状态。以下是上一轮静态检查发现的问题，**先确认它们是否仍存在**；如果已经修复，保留现有实现并转去处理剩余事项：

1. `Controls/SettingCard` 未明确暴露并传递右侧操作控件，`ContentPresenter` 没有绑定到对应内容属性。
2. 主窗口初次显示“通用”页时没有同步记录当前页面类型，直接打开侧栏截图演示后可能无法恢复正确的导航选中项。
3. “松开鼠标后确认”的标题、说明和开关语义不一致。
4. 外观页的强调色和卡片密度选项只保存了演示值，未即时改变实际视觉效果。
5. 截图演示中的极小选区和方向键移动缺少完整的边界处理。

## 3. 优先级与任务

### P0：修复设置卡片内容槽

- 为 `SettingCard` 明确提供右侧操作控件的内容属性，例如 `ActionContent` 依赖属性，或采用合适的自定义 `ContentControl` 实现。
- 确保 XAML 中 `ContentPresenter` 显式显示这个属性，且外部设置的 ComboBox、ToggleSwitch、Button、快捷键组合不会覆盖卡片自身的图标、标题和说明布局。
- 更新所有设置页的 `SettingCard` 用法，保证每张卡片都能同时显示左侧信息和右侧控件。
- 兼容不同操作控件的自然宽度；页面变窄时允许文字换行或卡片转为上下布局，不得裁掉控件。

### P0：修复导航状态恢复

- 初始化主窗口时，在导航到“通用”页的同时记录其页面类型。
- 通过侧栏“打开截图选区演示”打开独立演示窗后，侧栏仍显示原设置页为选中状态，不能变成无选中或错误选中。
- 从任意设置页打开演示窗口，关闭演示窗口后主窗口页面不变。
- 导航切页时页面标题、侧栏选中态和实际页面保持一致。

### P1：统一设置语义与演示状态

- 将选区设置改成准确表达实际演示的语义，例如“选区后显示确认工具条”。开启时，松开鼠标显示确认 / 取消工具条；需要用户确认后才进入结果演示。关闭时的行为也要清楚说明。
- 通用页中的“开机自动启动”等系统设置要标注为原型状态；关闭应用不会修改系统启动项。
- 快捷键页的“编辑”和“恢复默认”需真正更新**内存中的演示值**。编辑可使用 ContentDialog / 简单输入框；不得注册全局热键。恢复默认必须重置界面值，不能只显示“已恢复”提示。
- 对复制、翻译、放大镜等不接后端的操作继续显示明确演示反馈。文案不能声称真实写入剪贴板、识别文字或调用在线服务。
- 检查翻译页服务商切换时的表单呈现：根据所选服务显示或隐藏对应演示字段；所有 API 地址、模型和密钥输入均不得保存、读取或发送。

### P1：让外观选项产生一致的前端预览

- 强调色选项被选中时，实际即时应用到侧栏选中提示、主按钮和选区边框等强调元素；重新打开外观页后选中状态与当前演示值一致。
- “卡片密度”切换后确实改变设置卡片的内边距 / 高度，并作用于所有设置页；如果无法合理实现，则从本阶段 UI 移除此选项或明确显示为不可用，避免提供无效果的假控件。
- 主题在“跟随系统 / 浅色 / 深色”间切换后，主窗口、设置页、InfoBar、模拟截图窗口和结果窗口都保持可读，不出现固定颜色造成的文字对比问题。
- 定义少量统一的主题资源，避免各页面重复硬编码颜色、字号、卡片边距和按钮状态。

### P1：完善截图选区演示

- 所有选区更新和键盘微调都限制在演示窗口客户区内；调整窗口大小后选区、尺寸标签和工具条重新定位，不能跑出窗口或被裁切。
- 小于最小宽 / 高的拖动要一致处理：恢复上一个有效选区，或显示明确提示并禁止确认；不得留下看似有效但无法辨认的零碎选区。
- 限制指针按键类型，避免右键 / 中键按下误启动矩形选区。
- 确保键盘微调与 Enter / Esc 行为可触达：窗口打开后有合适焦点；焦点在工具条控件上时，不吞掉用户正常的 Tab / 方向键导航。
- 自由圈选当前如果仍是矩形模拟，应明确显示这是模拟状态；优先用 Canvas / Path 做一个简单自由路径预览。如果实现会明显扩大范围，则禁用该选项并标注“当前仅演示矩形”，不要让用户误以为自由形状已生效。

### P2：页面布局与视觉打磨

- 保持 Lyricify 设置页的组织逻辑：左侧导航 + 右侧单一滚动内容区 + 分组卡片；不要增加不必要的仪表盘、装饰面板或多余页面。
- 检查固定窗口尺寸、最小尺寸、导航宽度、页面最大内容宽度、卡片列宽和左右留白之间的关系；默认窗口下主要内容应舒展，不应大片空白或拥挤。
- 翻译页 API 表单在较窄宽度时改为上下排列，避免 360px 最小宽度字段挤出卡片。
- 对中英文混排、长描述、超长快捷键和较长 API 地址检查换行与截断；控件对齐不受文本长度影响。
- 检查卡片高度、图标尺寸、标题 / 描述字号、分组标题间距、按钮宽度和选中态视觉的一致性。
- 保持默认深色主题作为主视觉；浅色和跟随系统主题仍应完成基本适配。
- 使用 WinUI 自带控件和 Fluent 图标字形，不添加新的 UI 框架、WebView 或大型第三方依赖。

### P2：交互与无障碍收尾

- 全部导航项、按钮、下拉框、开关具有可见悬停 / 焦点 / 禁用状态；键盘 Tab 顺序自然。
- 按钮文案与实际动作一致；只有提示信息的动作应呈现为明确的“演示”或“了解”操作。
- 检查深色与浅色文字对比、图标语义和屏幕缩放下的可读性。
- InfoBar 等提示不会遮住关键控件；可关闭，并在合理时间后消失。

## 4. 本阶段禁止接入的功能

- 不调用、不启动 Python 子进程，不新增进程间通信。
- 不做真实屏幕截图、系统级截图遮罩、真实 OCR 或模型加载。
- 不发送翻译 API / HTTP 请求，不读写 API 密钥。
- 不注册系统全局快捷键，不创建系统托盘，不设置开机启动。
- 不读取或写入真实配置文件，不访问系统剪贴板。
- 不迁移、删除或重构现有 Python 代码，不改变 Python 版运行入口。
- 不为实现视觉细节下载大体积依赖或资产。

## 5. 修改范围与建议结构

所有代码修改限制在 `winui/ScreenLens.WinUI/`。重点关注：

- `Controls/SettingCard.xaml` 与 `.xaml.cs`：内容槽和自适应布局。
- `MainWindow.xaml` 与 `.xaml.cs`：导航、主内容区和主题。
- `ViewModels/DemoSettings.cs`：快捷键、强调色、密度等内存演示状态。
- `Views/Settings/`：设置语义、表单布局和各页面的状态反馈。
- `Views/Preview/`：选区边界、键盘与结果演示。
- `Styles/ThemeResources.xaml`：主题色、强调色、间距与控件样式。

按现有目录增量修改，保留 Visual Studio 模板文件和项目配置；不要为了整理代码重建解决方案。

## 6. 验收标准

1. 每一张 `SettingCard` 都能正确显示图标、标题、描述和右侧控件；切换页面后内容仍完整。
2. 从初始页以及任意设置页打开 / 关闭截图演示，主窗口导航页和选中态都正确。
3. 选区相关说明与演示行为完全一致；最小尺寸、窗口边缘、窗口缩放和方向键移动不会让选区越界。
4. 主题、强调色、卡片密度（若保留）均会产生可见且一致的前端效果，且仅存在内存中。
5. 快捷键编辑和重置会改变页面显示的演示值，但不会影响操作系统快捷键。
6. 翻译 / 复制 / 截图操作均清楚标注模拟状态，不发生网络、剪贴板、OCR 或真实屏幕访问。
7. 默认窗口及窄窗口下，卡片控件不溢出、不重叠，长文本可以换行或滚动。
8. WinUI 项目可在 Visual Studio 中生成并启动；完成汇报需说明是否进行过构建 / 运行验证。不要运行 Python 版或 Python 测试。
9. 汇报列出修复的问题、主要视觉调整、仍未接入的功能以及 WinUI 项目启动方式。
